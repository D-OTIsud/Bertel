# Thesaurus endpoint and contract coverage audit — 2026-11-10

## Scope and evidence

This matrix follows the public Next.js route handlers under `bertel-tourism-ui/src/app/api/public/thesaurus`, the shared request parser/projection in `bertel-tourism-ui/src/lib/thesaurus-api.ts`, and the published OpenAPI/partner guide/Postman collection. It records only the public read contract; partner authentication and rate limiting apply before parameter validation and content lookup.

All routes require a bearer partner key. Success responses have `ETag`, `Cache-Control: private, no-cache`, `X-Bertel-Vocabulary-Release`, and `Content-Type`; matching `If-None-Match` returns bodyless `304` after auth/rate admission. ETags are computed over representation content type and serialized representation. Before the explicit launch freeze, the public history consists only of edition 1, which reads the latest selected technical snapshot; each response's ETag and cursors remain bound to that actual snapshot, and a retouch can invalidate them. Errors are flat `{ "error": ... }` objects. Authentication `401`, rate limit `429`, unavailable snapshot `503`, and upstream/configuration failures are common.

## Endpoint matrix

| `GET /thesaurus/releases/{releaseId}/export` | `export` | `domains`, `status`, `lang`, `format`, `If-None-Match` | `lang=fr`; `format=json`; JSON or JSON-LD | Full filtered export; JSON-LD is standalone `application/ld+json` graph with Bertel membership predicates when snapshot fields exist |

`domains` and `status` are accepted only for concepts, changes, and export. They are explicitly rejected on discovery manifest, release manifest, and single-concept routes. Missing `status` means all lifecycle values, not active-only. Unknown/repeated query names, repeated scalar parameters, malformed lists (over 100 entries), invalid BCP 47 language tags (over 35 characters), invalid page sizes/formats, and incompatible cursors produce `400`. Release and concept path identifiers are validated separately. Unknown/non-public domain behavior is a generic client error and must not disclose private vocabularies.

Comma-separated `domains` and `status` lists are trimmed, validated, deduplicated, and normalized before filtering. A pagination cursor is opaque and bound to the release, action, normalized filters, language, query, page size, and representation format. `cursor` is meaningful only on release-pinned paged routes.

## Localization and immutable snapshot rules

Concept records preserve the complete `preferred_labels` and `definitions` language maps and expose localized `name` and `description` where available, plus per-concept `requested_lang`, `effective_lang`, and `definition_lang`. `requested_lang` is present; `effective_lang` and `definition_lang` are present and nullable. Fallback order for a localized name/definition is exact requested tag, primary language, then French. A legacy scalar French `name`/`description` is retained and labeled `fr` when no language map matches; no French entry is added to the maps. If no scalar exists, the corresponding effective language is null.

When a frozen concept document carries native action/group membership, the HTTP concept projection preserves optional `member_of` and `members` arrays of unique UUIDs. `member_of` identifies the action's native group; `members` identifies a group's native actions. Each field is omitted when the snapshot lacks it, including older releases; the adapter never synthesizes `[]` or performs a live-source lookup. Membership edges are emitted only when both endpoint vocabularies are public and governed in that snapshot. A group snapshot may carry members: [] when it has no eligible actions; the HTTP projection preserves that frozen empty array, while older snapshots lacking the field keep it absent. It is independent of the existing category `context_key` and `broader` edges, including the two supported cross-category native memberships. JSON-LD uses `bertel:memberOf` and `bertel:member` references with `@id`, leaving `skos:broader` unchanged. These fields describe the snapshot contract when those adapters are present; they do not assert that a deployment or publication has occurred.

New checksummed domain records preserve their full `name_i18n` maps and add localized `name`, `requested_lang`, and `effective_lang`, without augmentation from current metadata or application dictionaries. Domain fallback is exact requested tag, primary language, then French. Legacy manifests retain the approved master behavior: a versioned dictionary may supply English only when the stored French title exactly matches a reviewed alias for that domain; stored translations take priority, and an unknown/custom title falls back to its historical French scalar. This is an HTTP representation and never a historical database rewrite. `name_metadata_scope` qualifies the map/scalar provenance as `release_snapshot`, `reviewed_legacy_dictionary` or `legacy_scalar`. Discovery may include release-history records with `is_current` measured against that response's current `meta.release_id`; a standalone historical release response does not label itself current.

`metadata_checksum` appears in the manifest data and in envelope `meta` when supplied by the pinned snapshot. It is the PostgreSQL JSONB `domains::text` MD5, distinct from the existing concept-content checksum; old releases may omit it. `data.metadata_scope` is `release_snapshot` on both the discovery manifest and a standalone release manifest. Neither `effective_lang` nor `definition_lang` is claimed as a top-level discovery/release response property. All translated maps survive JSON-LD serialization as language-indexed SKOS properties. Historical releases remain immutable, including their original name maps and checksums.

## OpenAPI and client examples

`docs/openapi.json` is normative for paths, parameter acceptance, defaults, bounds, response shapes, and errors. `docs/guide-partenaires.md` explains synchronization and fallback behavior. The Postman collection has credential-free examples; users must supply `partner_key` locally. Localization examples exercise `fr`, `en`, `es`, `de`, and a regional tag; negative examples check rejected `domains`/`status` on routes where those filters are unsupported. Never request or extract a key in a distributed collection.

## Release and historical coverage notes

The public series remains at edition `1` through pre-launch retouches, backed by the latest selected technical snapshot; technical preparation IDs are not exposed. Discovery history contains only edition 1, `previous_release_id` is null, and its changes feed enumerates all public concepts in the selected snapshot as added. ETags and cursors are tied to the selected snapshot so a retouch does not silently continue an old page walk. At explicit freeze, edition 1 becomes the immutable baseline; later official publications can advance the public series. Current-release assertions must not be applied to snapshots that lack `name_i18n` or `metadata_checksum`. Concept `checksum` behavior remains unchanged; metadata checksums describe release metadata separately. Discovery and release manifests remain distinct representations and yield distinct ETags when their bodies differ.
